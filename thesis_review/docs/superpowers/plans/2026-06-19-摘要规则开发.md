# 摘要规则开发实施计划

## 目标

使用 TDD 开发 `abstract` 摘要模块规则检查器，让 `thesis_review/docs/rules/abstract/samples/` 下已手工制作的 Word 样本命中 `abstract/case.yml` 中定义的规则。开发完成并验证通过后，只把已实现、已测试、已由样本覆盖的摘要规则从 `draft` 改为 `active`。

## 总体策略

- 直接重构，不保留旧分区命名兼容。
- 把当前 `abstract_cn`、`abstract_en` 重构为清晰的新分区命名，例如 `abstract`、`abstract-chinese`、`abstract-english`。
- 新增摘要规则检查器，按中文摘要标题/正文、中文关键词、英文摘要标题/正文、英文关键词分组。
- 每组规则严格走 TDD：先写失败测试，再实现，再跑绿。
- 真实 Word 样本只作为 UNO 集成验证，不替代纯 Python 单元测试。
- 如果样本命中和 `case.yml` 不一致，先用 docx/UNO 抽取结果验证样本，不直接改代码迁就样本。

## 风险处理

- Word 样本手误：先用 docx/UNO 抽取验证，不直接改代码迁就。
- Word 自动拆 run：检查器按文本范围判断，不假设一个段落只有一个 run。
- 字体字段为空：记录为“未识别”，不要静默通过。
- 中英文混排：中文看 `font_east_asian`，英文内容看 `font_latin`。
- 英文关键词标点：中文全角冒号、中文分号按宋体；关键词内容按 Times New Roman。
- 范围失控：只激活本轮样本覆盖的规则，剩余规则继续 `draft`。
