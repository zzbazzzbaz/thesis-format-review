# 第二阶段对象与页眉页脚规则设计

## 目标

第二阶段实现第一阶段明确暂缓的对象级和页面级规则：`global` 页眉、正文到附录页脚页码格式，以及 `main-text` 公式、图片图题、表格表题规则。

本阶段只扩展抽取、模型和规则实现，不新增或修改任何真实 Word 样本。已有 `docs/rules/**/samples/*.docx` 只作为只读验收输入。实现不得面向 `case.yml`、样本文件名、固定 `flow_index` 或样本文本答案编程，所有判断必须来自 `DocumentModel` 中的通用结构、格式值和相邻关系。

## 当前上下文

当前运行时链路是：

```text
UNO extractor -> DocumentModel -> detect_sections/build_rule_context -> registered checkers -> IssueFactory -> issues.json/marked.docx
```

第一阶段已经实现并激活：

- `cover`
- `references`
- `acknowledgements`
- `appendix`
- `main-text` 标题、普通段落、正文参考文献引用

`main-text` 中的公式、图片图题、表格表题仍为 `draft`。`global` 中可稳定实现的页眉和页脚页码格式仍为 `draft`，页边距、页码连续性和封面/摘要/目录无页码规则已标记为 `deprecated`。

现有模型能力限制：

- `TableBlock` 已经进入统一文档流，可用于判断表题与表格的相邻关系。
- `ImageBlock` 类型已存在，但 UNO traversal/extractor 尚未真正产出图片块。
- `PageStyleInfo` 只预留了 `header_text`、`footer_text` 字段，尚未抽取页眉页脚段落、run 格式、页码字段和页面样式适用范围。
- `ParagraphBlock` 尚不能表达公式/数学对象、制表位等用于判断公式编号位置的结构信息。

## 设计取舍

### 方案 A：继续使用段落文本启发式

只靠现有 `ParagraphBlock.text` 正则识别公式、图题、表题和页码。这一方案改动小，但无法稳定判断图片是否存在、图题是否真的位于图片下方、页脚页码是否是页码字段，也无法区分页眉页脚格式与正文段落格式。

不采用。

### 方案 B：扩展统一文档模型，规则基于对象和相邻关系

补齐图片块、页眉页脚格式、公式候选结构和制表位等抽取能力。规则层只消费 `DocumentModel`，通过 section 范围、块相邻关系、页样式适用范围和 run 级格式判断规则。

采用此方案。它与现有架构一致，能保持规则代码可测试，并避免为某个 Word 样本写特殊分支。

### 方案 C：完全改为 OOXML 静态解析

直接解析 `.docx` XML 判断所有对象和格式。这一方案能看到部分 UNO 没有暴露的结构，但有效字体、字号、样式继承和 WPS/LibreOffice 兼容行为会变复杂，且会绕开当前以 UNO 有效格式为准的项目原则。

不整体采用。仅当 UNO 无法稳定暴露某个结构元数据时，可增加只读 OOXML 辅助抽取，并把结果映射回 `DocumentModel`。最终规则仍只消费统一模型。

## 非面向答案约束

实现必须满足以下约束：

- 不读取 `case.yml` 来决定规则是否命中。
- 不读取样本文件名、case id 或目录名来决定规则是否命中。
- 不在 checker 中硬编码某个样本的段落序号、flow index、具体正文句子或对象数量。
- 不修改、复制、重保存任何 `docs/rules/**/samples/*.docx`。
- 不用 `python-docx` 作为最终格式判定来源；可在测试中临时生成输入文档，但断言必须基于 UNO/模型抽取结果。
- 不通过硬编码 `message`、`expected`、`severity` 创建 issue，仍统一使用 `IssueFactory.create(rule_id=..., actual=..., location=...)`。

## 数据模型变更

### 页眉页脚格式模型

新增轻量格式 run，避免把正文 `RunSpan.id` 定位语义复用到页眉页脚：

```python
class FormattedTextRun(BaseModel):
    text: str
    run_index: int
    font_east_asian: str | None = None
    font_latin: str | None = None
    size_pt: float | None = None
    bold: bool = False
    italic: bool = False
```

新增页眉页脚段落：

```python
class HeaderFooterParagraph(BaseModel):
    text: str
    paragraph_index: int
    alignment: str | None = None
    runs: list[FormattedTextRun] = []
    has_page_number_field: bool = False
    page_number_text: str | None = None
    page_number_format: Literal["arabic", "roman", "unknown"] | None = None
```

扩展 `PageStyleInfo`，保留原有 `header_text`、`footer_text` 字段以兼容旧代码：

```python
class PageStyleInfo(BaseModel):
    name: str
    width_mm: float | None = None
    height_mm: float | None = None
    margin_top_mm: float | None = None
    margin_bottom_mm: float | None = None
    margin_left_mm: float | None = None
    margin_right_mm: float | None = None
    header_text: str | None = None
    footer_text: str | None = None
    header_paragraphs: list[HeaderFooterParagraph] = []
    footer_paragraphs: list[HeaderFooterParagraph] = []
```

`header_text` 和 `footer_text` 为对应段落文本按换行拼接后的可见文本。

### 块所属页面样式

扩展 `BlockBase`：

```python
class BlockBase(BaseModel):
    id: str
    kind: BlockKind
    flow_index: int
    type_index: int
    page_style_name: str | None = None
```

extractor 在遍历正文流时读取并传播当前页面样式名。规则层通过 section 内 blocks 的 `page_style_name` 集合判断哪些页面样式需要检查页眉或页脚。

该字段不是渲染页号，不表达“第几页”，只表达文档流中该块应用的页面样式名称。

### 段落制表位与公式标记

新增：

```python
class TabStopInfo(BaseModel):
    position_mm: float | None = None
    alignment: Literal["left", "center", "right", "decimal", "unknown"] = "unknown"
```

扩展 `ParagraphBlock`：

```python
class ParagraphBlock(BlockBase):
    ...
    contains_math: bool = False
    math_object_count: int = 0
    tab_stops: list[TabStopInfo] = []
```

`contains_math` 表示段落中存在 UNO 可识别的数学对象，或只读 OOXML 辅助抽取发现该段落包含 `m:oMath` / `m:oMathPara`。它只作为公式候选证据之一，不直接等同于规则命中。

## 抽取设计

### 页样式、页眉、页脚

extractor 增加页面样式抽取：

- 枚举 UNO `PageStyles`。
- 读取每个 page style 的页眉、页脚文本对象。
- 对页眉页脚中的段落抽取：
  - 可见文本。
  - 对齐方式。
  - run 字体、字号、粗体、斜体。
  - 页码字段标记。
  - 页码字段的显示文本和编号类型。

页码字段抽取规则：

- 如果 UNO 暴露字段类型为 page number，标记 `has_page_number_field=True`。
- 如果可取得编号类型，映射为 `arabic`、`roman` 或 `unknown`。
- 如果 UNO 只给出可见文本，则用可见文本辅助判断；纯 ASCII 数字视为 `arabic`，罗马数字视为 `roman`，其他为 `unknown`。
- 字体和字号以页码字段所在 text portion 或其可见文本 run 的有效格式为准。

块所属页面样式抽取规则：

- 读取段落的显式页面样式属性作为页面样式切换点。
- 后续块继承最近一次识别到的页面样式名。
- 表格和图片继承其锚点或前置正文流位置的当前页面样式。
- 如果整个文档无法识别任何页面样式名，global checker 不猜测、不报错；应由 extractor 测试失败暴露抽取缺口。

### 图片块

`traversal.blocks(doc)` 必须产出正文流中的图片对象：

- 图片块使用现有 `ImageBlock`。
- `type_index` 按图片出现顺序递增。
- `flow_index` 与段落、表格共享同一个文档流序列。
- 图片锚定到段落时，优先把图片块放在锚点段落之后；如果 UNO 能提供更精确的 inline 顺序，则按 inline 顺序放置。
- 多张图片锚定到同一段落时，保持 UNO 枚举顺序。
- 无法映射到正文流的页眉、页脚、封面装饰图片不进入正文 `blocks`；正文规则只在 `main-text` section 内检查图片。

图片抽取失败不能通过样本文件名绕过。若某类真实正文图片不能映射，应增加抽取测试并修正 traversal。

### 公式候选

公式不新增 `FormulaBlock`。公式在 Word/WPS/LibreOffice 中可能表现为数学对象、普通文本表达式或嵌入对象；本阶段把公式识别作为规则层对象识别，底层只提供必要证据。

extractor 提供：

- `ParagraphBlock.contains_math`
- `ParagraphBlock.math_object_count`
- `ParagraphBlock.tab_stops`
- 原有 run 字体、字号和段落对齐

checker 构造公式候选时使用通用证据：

- 段落 `contains_math=True`。
- 段落样式名包含 `公式` 或 `Equation`。
- 段落文本为孤立的数学表达式行，且包含 `=`、运算符、上下标符号、希腊字母或括号编号等公式特征。

公式候选识别必须排除：

- 正文标题。
- 图题、表题。
- 参考文献引用。
- 普通叙述句中短的行内表达式，例如“由式(3-1)给出”。

## 对象识别

所有对象识别都限制在 `sections["main-text"]` 范围内。

### 章节上下文

图片、表格和公式编号都按一级标题章节编号计数。章节上下文来自正文 section 中已识别的一级标题：

- 一级标题文本形如 `第X章  标题`。
- `X` 使用中文数字时转换为阿拉伯数字。
- 当前章节从一级标题开始，持续到下一个一级标题之前。
- 如果对象位于无法识别章节编号的范围内，编号规则报告 `actual="未识别章节"`。

每个章节内分别维护公式、图片、表格计数器。计数按对象在 `blocks` 中的顺序递增。

### 公式单元

公式单元由一个公式候选段落和可选编号组成。

合法编号 token：

```text
(章号-序号)
（章号-序号）
```

编号可位于：

- 公式候选段落内。
- 紧邻公式候选段落之后的第一个非空段落内，且该段落只包含编号 token。

如果公式候选段落和编号段落之间存在非空正文、图片或表格，则不视为同一个公式单元。

### 图片与图题

图片对象是 `main-text` section 内的 `ImageBlock`。

图题候选是规范化后以 `图` 开头并包含章节编号形态的段落，例如：

```text
图3-1 过阻尼响应
```

图片与图题配对规则：

- 图片的图题应是图片之后第一个非空 `ParagraphBlock`。
- 空段落不打断配对。
- 如果图片之后第一个非空块不是图题段落，则该图片缺少图题。
- 如果图题段落不是某个图片之后第一个非空段落，则该图题位置错误。

图片计数按 `ImageBlock` 在当前章节中的出现顺序计算。缺少图题的图片仍参与计数，避免后续图片编号被错误宽容。

### 表格与表题

表格对象是 `main-text` section 内的 `TableBlock`。

表题候选是规范化后以 `表` 开头并包含章节编号形态的段落，例如：

```text
表4-1 激光入射功率密度对导轨滚道表面硬化层和显微硬度的影响
```

表格与表题配对规则：

- 表格的表题应是表格之前第一个非空 `ParagraphBlock`。
- 空段落不打断配对。
- 如果表格之前第一个非空块不是表题段落，则该表格缺少表题。
- 如果表题段落不是某个表格之前第一个非空段落，则该表题位置错误。

表格计数按 `TableBlock` 在当前章节中的出现顺序计算。缺少表题的表格仍参与计数。

`续表` 段落不作为新表格表题，不参与本阶段表题格式检查。

## 规则设计

### 页眉规则

适用范围：

- 中文摘要。
- 英文摘要。
- 目录。
- 正文。
- 参考文献。
- 致谢。
- 附录。

不检查只作用于封面 section 的页面样式。

页面样式集合来自上述 section 内 blocks 的 `page_style_name`。同一个页面样式只检查一次。issue 定位锚定到该页面样式第一次出现在适用 section 的块，避免把页眉页脚问题错误定位到随机正文段落。

检查内容：

- `global-header-001`：页眉可见文本去除首尾空白后必须严格等于 `山东石油化工学院本科毕业设计（论文）`。
- `global-header-002`：页眉中包含中文文本或中文标点的 run 必须使用中文字体 `黑体`。
- `global-header-003`：页眉所有可见 run 字号必须为 `10.5pt`。
- `global-header-004`：承载页眉文本的段落必须居中。

如果页眉不存在或无可见文本：

- `global-header-001` 报告 `actual="未识别"`。
- 字体、字号、居中规则不额外报告，避免同一缺失对象产生过多噪声。

### 页脚页码规则

适用范围：

- 正文。
- 参考文献。
- 致谢。
- 附录。

不检查封面、摘要和目录的无页码要求，因为对应规则已 `deprecated`。

页码段落识别：

- 优先选择 `has_page_number_field=True` 的页脚段落。
- 如果没有页码字段，则选择可见文本去除空白后为纯数字或罗马数字的页脚段落。
- 如果仍无法识别页码段落，`global-footer-page-number-001` 报告 `actual="未识别页码"`，其他页码格式规则不额外报告。

检查内容：

- `global-footer-page-number-001`：页码必须为阿拉伯数字。`page_number_format=="arabic"` 或可见页码文本匹配 ASCII 数字时通过。
- `global-footer-page-number-003`：页码段落必须居中。
- `global-footer-page-number-004`：页码字段或页码可见文本 run 的西文字体必须为 `Times New Roman`。
- `global-footer-page-number-005`：页码字段或页码可见文本 run 的字号必须为 `10.5pt`。

不检查页码起始值和连续性。

### 公式规则

每个公式候选段落最多生成一个公式单元。

检查内容：

- `main-text-formula-001`：公式单元必须有编号 token。
- `main-text-formula-002`：编号必须匹配当前章节内公式序号，例如第 3 章第 1 个公式为 `(3-1)` 或 `（3-1）`。
- `main-text-formula-003`：公式主体必须居中。
- `main-text-formula-004`：公式编号必须居右。
- `main-text-formula-005`：公式编号 run 字号必须为 `10.5pt`。
- `main-text-formula-006`：公式编号 run 西文字体必须为 `Times New Roman`。

居中和居右判定：

- 如果公式主体和编号在两个段落中，公式主体段落 `alignment=="center"` 视为主体居中，编号段落 `alignment=="right"` 视为编号居右。
- 如果公式主体和编号在同一段落中，段落必须包含居中制表位和居右制表位；编号 token 必须位于居右制表位之后。
- 如果段落没有可识别的制表位且公式主体和编号在同一段落中，`main-text-formula-003` 或 `main-text-formula-004` 按缺失项报告 `actual="未识别"`。

字体和字号定位到编号 token 覆盖的第一个失败 run。编号缺失时只报告 `main-text-formula-001`，不报告编号字体和字号。

### 图片图题规则

每个 `ImageBlock` 必须有图题。每个图题候选必须位于对应图片下方。

检查内容：

- `main-text-figure-caption-001`：图片必须有图题。
- `main-text-figure-caption-002`：图题必须位于图片下方。
- `main-text-figure-caption-003`：图号必须匹配当前章节内图片序号，例如 `图3-1`。
- `main-text-figure-caption-004`：图号和图题文本之间必须正好有 1 个普通半角空格。
- `main-text-figure-caption-005`：图题段落必须居中。
- `main-text-figure-caption-006`：图题所有可见 run 字号必须为 `10.5pt`。
- `main-text-figure-caption-007`：图题中包含中文文本或中文标点的 run 必须使用中文字体 `宋体`。

定位策略：

- 缺少图题定位到 `ImageBlock`。
- 图题位置错误、图号格式、图号后空格、居中定位到图题段落。
- 图题字号和中文字体定位到第一个失败 run。

### 表格表题规则

每个 `TableBlock` 必须有表题。每个表题候选必须位于对应表格上方。

检查内容：

- `main-text-table-caption-001`：表格必须有表题。
- `main-text-table-caption-002`：表题必须位于表格上方。
- `main-text-table-caption-003`：表号必须匹配当前章节内表格序号，例如 `表4-1`。
- `main-text-table-caption-004`：表号和表题文本之间必须正好有 1 个普通半角空格。
- `main-text-table-caption-005`：表题段落必须居中。
- `main-text-table-caption-006`：表题所有可见 run 字号必须为 `10.5pt`。
- `main-text-table-caption-007`：表题中包含中文文本或中文标点的 run 必须使用中文字体 `宋体`。

定位策略：

- 缺少表题定位到 `TableBlock`。
- 表题位置错误、表号格式、表号后空格、居中定位到表题段落。
- 表题字号和中文字体定位到第一个失败 run。

## 错误上报

所有 issue 仍通过：

```python
context.issue_factory.create(rule_id=..., actual=..., location=...)
```

规则代码不得硬编码 `message`、`expected` 或 `severity`。

`actual` 取值规则：

- 字体缺失：`未识别`
- 字号缺失：`未识别`
- 对齐缺失：`未识别`
- 页码缺失：`未识别页码`
- 章节上下文缺失：`未识别章节`
- 缺少图题、表题、公式编号：使用 `未找到`
- 编号不匹配：使用实际编号 token；没有 token 时由存在性规则报告，不重复报告编号规则

同一对象内同一 run 级规则只报告第一个失败 run，避免批注噪声过多。

`ImageBlock`、`TableBlock` 缺失题注问题可以进入 `issues.json`。当前 annotator 对非段落块级 issue 仍可记录 warning 并跳过标注；第二阶段不强制实现图片和表格块的可视化标注。
