# 第一阶段文本格式规则设计

## 目标

实现当前已准备好测试 Word 样本的第一批规则模块，并把范围限定在段落和 run 级别即可判定的格式检查上。本阶段覆盖 `cover`、`references`、`acknowledgements`、`appendix`，以及 `main-text` 中的标题、普通段落和正文参考文献引用规则。

`main-text` 中的公式、图片题注和表格题注规则不在本阶段实现。这些规则需要更完整的块级抽取、图片/公式识别和对象相邻关系判断，后续单独编写第二份 spec。

## 当前上下文

运行时审核链路已经存在：

```text
UNO extractor -> DocumentModel -> detect_sections/build_rule_context -> registered checkers -> IssueFactory -> issues.json/marked.docx
```

当前已实现的规则模块是 `abstract` 和 `table-of-contents`。新模块的 `rule.yml`、`case.yml` 和人工编写的 Word 样本已经放在 `thesis_review/docs/rules/**` 下。轻量规则资产契约测试当前可以通过。

样本来源会影响验收：

- `appendix`、`references`、`cover` 样本由 Windows 电脑上的 WPS 编辑。
- `acknowledgements`、`main-text` 样本由 macOS 电脑上的 WPS 编辑。

规则实现不按样本来源分支处理。格式判定统一以容器内 LibreOffice/UNO 抽取到的有效格式值为准。

## 架构

继续使用现有 checker 架构，新增聚焦的规则模块，不引入 YAML 驱动的通用规则引擎。新代码遵循 `abstract_rules.py` 和 `toc_rules.py` 的本地模式。

新增一个小型共享格式 helper 模块，用来承载重复机制：

- 构造 block 和 run 的 `Location`。
- 枚举 section 段落、过滤非空段落。
- 统计某个段落前后连续空段落数量。
- 判断并格式化字体、字号、加粗、行距、首行缩进、对齐和上标。
- 统一生成 `actual` 字符串，例如 `12pt`、`1.5 倍`、`2 字符`、`居中`、`两端对齐`、`未识别`。
- 对同一段落内的同一 run 级规则只追加第一个错误 run，避免批注噪声过多。

本阶段不迁移 `abstract_rules.py` 和 `toc_rules.py` 的内部 helper，避免扩大改动面。

新增规则模块：

- `thesis_review/src/thesis_review/rules/cover_rules.py`
- `thesis_review/src/thesis_review/rules/references_rules.py`
- `thesis_review/src/thesis_review/rules/acknowledgements_rules.py`
- `thesis_review/src/thesis_review/rules/appendix_rules.py`
- `thesis_review/src/thesis_review/rules/main_text_rules.py`

在 `thesis_review/src/thesis_review/rules/registry.py` 注册这些 checker。

## 数据模型变更

给 `RunSpan` 增加字段：

```python
superscript: bool = False
```

更新 `adapters.uno.extractor`，从 UNO run 属性读取上标信息。目标来源是 `CharEscapement`：大于 0 视为上标。该字段用于实现 `main-text-reference-citation-002`。

字段默认值为 `False`，保证现有测试和构造助手不需要大量同步改动。`tests/support/model_builders.py` 增加可选参数，供引用规则测试显式构造上标 run。

本阶段不增加新的块级模型字段。

## 对象识别

所有对象识别都限制在 `detect_sections()` 给出的 section 范围内，避免误扫目录条目或后续模块内容。

### 封面

使用 `sections["cover"]`，范围是文档开头到摘要之前。

识别对象：

- 题目行：规范化文本以 `题目` 开头的第一个非空段落，例如 `题    目：...`。
- 信息行：规范化文本以 `学生姓名`、`学号`、`院系`、`专业年级`、`指导教师` 开头的非空段落。
- 日期行：封面 section 中同时包含 `年`、`月`、`日` 的非空段落。

检查内容：

- 题目行：中文字体 `黑体`，字号 `18pt`。
- 信息行：中文字体 `仿宋`，字号 `16pt`，加粗。
- 日期行：中文字体 `仿宋`，字号 `16pt`，加粗。

本阶段不报告封面字段缺失。如果找不到某类对象，不为该对象产生 issue。

### 致谢与附录

分别使用 `sections["acknowledgements"]` 和 `sections["appendix"]`。

每个 section 的识别规则：

- 标题是 section 内第一个非空段落。
- 标题文本必须分别严格为 `致    谢` 或 `附    录`。
- 标题字体为 `黑体`，字号为 `16pt`，对齐为居中。
- 标题后必须正好有 1 个空段落。
- 正文是标题及其后连续空段落之后的非空段落。

正文检查：

- 字号 `12pt`。
- 中文字体 `宋体`。
- 仅对包含 ASCII 字母或数字的 run 检查西文/数字字体 `Times New Roman`。
- 行距 `1.5` 倍。
- 首行缩进 `2` 字符。
- 对齐为 `justify`，展示为“两端对齐”。

`附录A...` 这类附录小节文字在本阶段按附录正文处理，不单独建立附录小标题规则。

### 参考文献

使用 `sections["references"]`。

标题是 section 内第一个非空段落。

检查内容：

- 标题文本必须严格为 `参考文献`。
- 标题后必须正好有 1 个空段落。
- 条目段落是标题及其后连续空段落之后的非空段落。
- 条目编号必须以 `[\d+]` 开头。
- 编号与条目正文之间必须正好有 1 个普通半角空格。
- 条目段落行距为 `1.5` 倍。
- 条目可见 run 字号为 `12pt`。
- 包含中文文本的 run 使用中文字体 `宋体`。
- 包含 ASCII 字母或数字的 run 使用西文/数字字体 `Times New Roman`。

GB/T 7714 著录内容细节不在本阶段范围内。

### 正文

使用 `sections["main-text"]`。

标题识别：

- 一级标题候选：正文 section 内以 `第...章` 开头的非空段落，且不是目录条目。
- 二级标题候选：以 `N.N` 开头的段落。
- 三级标题候选：以 `N.N.N` 开头的段落。

一级标题检查：

- 编号形态必须为 `第X章`，其中 `X` 使用中文数字。
- 章编号和标题文本之间必须正好有 2 个半角空格。
- 中文字体 `黑体`。
- 字号 `16pt`。
- 标题后到正文前必须正好有 1 个空段落。
- 每个一级标题的 `page_break_before` 必须为 true。

二级标题检查：

- 编号形态为 `N.N`。
- 编号后必须正好有 1 个半角空格。
- 中文字体 `黑体`。
- 字号 `14pt`。
- 行距 `1.5` 倍。
- 包含 ASCII 字母或数字的 run 使用西文/数字字体 `Times New Roman`。

三级标题检查：

- 编号形态为 `N.N.N`。
- 编号后必须正好有 1 个半角空格。
- 首行缩进 `2` 字符。
- 中文字体 `黑体`。
- 字号 `12pt`。
- 行距 `1.5` 倍。
- 包含 ASCII 字母或数字的 run 使用西文/数字字体 `Times New Roman`。

普通段落检查：

- 排除空段落、已识别标题、图题、表题和疑似公式段落。
- 字号 `12pt`。
- 中文字体 `宋体`。
- 包含 ASCII 字母或数字的 run 使用西文/数字字体 `Times New Roman`。
- 首行缩进 `2` 字符，包括以 `（1）` 开头的段落。
- 行距 `1.5` 倍。
- 对齐为 `justify`。

正文参考文献引用检查：

- 在正文 section 的普通叙述段落中扫描。
- 引用候选是类似参考文献引用的方括号 token，包括 `[a1]` 这类错误示例。
- 合法引用文本为 `[数字]`。
- 每个引用候选的组成 run 都必须为上标。
- 引用 run 字号为 `12pt`。
- 引用 run 西文/数字字体为 `Times New Roman`。

本阶段不做正文引用与 `references` 条目的交叉匹配。

## 错误上报

所有 issue 都通过以下方式创建：

```python
context.issue_factory.create(rule_id=..., actual=..., location=...)
```

规则代码不得硬编码 `message`、`expected` 或 `severity`。

定位策略：

- 文本、编号空格、行距、缩进、对齐和段前分页问题定位到 paragraph block。
- run 级字体、字号、加粗和上标问题定位到具体 run。
- 同一段落内，同一条 run 级规则只报告第一个失败 run，避免大量重复批注。
- 不同段落中的同一 `rule_id` 可以多次报告。

必须判断的有效格式值缺失或无法识别时视为不满足要求，`actual` 写为 `未识别`。

字体检查按文本类型触发：

- 中文字体检查只作用于包含中文文本或中文标点的 run。
- 西文/数字字体检查只作用于包含 ASCII 字母或数字的 run。
- 纯空白 run 忽略。
