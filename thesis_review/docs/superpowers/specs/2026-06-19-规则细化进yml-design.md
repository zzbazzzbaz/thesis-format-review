# 规则细化进 yml 设计

日期：2026-06-19
状态：设计已确认，待实施计划

## 1. 背景

`docs/_chat/rule.md` 已经整理出毕业设计格式审核系统需要覆盖的完整格式规则。`thesis_review/docs/rules/README.md` 已经定义正式规则资产目录、`rule.yml` / `case.yml` 字段约束和维护流程。目前只有 `table-of-contents` 模块完成了结构化规则落地，其他模块仍停留在自然语言规范阶段。

本设计将 `rule.md` 中的规则边界、模块划分和原子规则粒度固定下来，作为后续把规则细化进各模块 `rule.yml` 的依据。

## 2. 目标

1. 固定第一轮规则模块划分。
2. 明确每个模块需要进入 `rule.yml` 的规则范围。
3. 明确不进入规则资产或暂不实现的规范项。
4. 保持现有 `rule.yml` schema 不变。
5. 用 `draft` 状态承载尚未实现的规则，避免把未实现能力误标为正式审核规则。

## 3. 非目标

- 不修改 `rule.yml` / `case.yml` schema。
- 不新增 `object`、`category`、`scope` 字段。
- 不在本设计阶段实现检查器代码。
- 不生成或编辑真实 `.docx` 样本。
- 不把所有规则一次性标记为 `active`。

## 4. 规则资产边界

`rule.yml` 继续只包含当前 loader 支持的字段：

```yaml
id: ...
title: ...
severity: error
status: draft
description: ...
message: ...
expected: ...
```

模块级字段仍为：

```yaml
module: ...
module_name: ...
rules:
  - ...
```

规则粒度继续使用：

```text
一个 rule id = 一个检查对象 + 一个判断条件 + 一条批注文案
```

第一轮新增规则默认：

- `severity: error`
- `status: draft`

已经实现并通过验证的目录规则保持 `active`。后续某条规则的检查器实现并测试通过后，再把该规则从 `draft` 调整为 `active`。

## 5. 模块划分

| 模块目录 / `module` | `module_name` | 规则范围 |
|---|---|---|
| `global` | 整体 | 页边距、页眉、页脚页码、无页码区域 |
| `cover` | 封面 | 封面题目、信息行、日期的样式 |
| `abstract` | 摘要 | 中文摘要、英文摘要、中文关键词、英文关键词 |
| `table-of-contents` | 目录 | 目录标题和目录条目，保持现有规则 |
| `main-text` | 正文 | 标题、普通段落、引用、公式、图、表 |
| `references` | 参考文献 | 标题、空行、条目编号空格、条目格式 |
| `acknowledgements` | 致谢 | 致谢标题、致谢正文 |
| `appendix` | 附录 | 附录标题、附录正文 |

`thesis_review/docs/rules/README.md` 需要随实施更新模块表：新增 `global`，将中文摘要和英文摘要合并为 `abstract`，确认致谢模块使用 `acknowledgements`。

## 6. 全局约定

- 规则中提到的空格，除非特别说明，均为普通半角空格。
- 标题中的 4 个空格必须是 4 个普通半角空格，不接受全角空格、制表符或其他空白。
- 页边距单位为厘米。
- 字号换算沿用 Word 常用值：小二 18pt，三号 16pt，四号 14pt，小四 12pt，五号 10.5pt。
- 中文字体规则主要检查东亚字体；西文和数字字体规则主要检查 Latin 字体。
- `case.yml` 仍只服务测试样本，不参与生产审核。

## 7. Global 模块规则

`global` 只包含页面级规则，不放正文默认字体、字号、行距等内容规则。

### 7.1 页边距

subject 使用 `global-margin-*`。

原子检查点：

- 上边距为 2.6 cm。
- 下边距为 2.6 cm。
- 左边距为 2.6 cm。
- 右边距为 2.6 cm。

页边距适用于所有页面。

### 7.2 页眉

subject 使用 `global-header-*`。

页眉不适用于封面。从中文摘要开始，到附录结束都需要检查页眉。

原子检查点：

- 页眉文本为 `山东石油化工学院本科毕业设计（论文）`。
- 页眉中文字体为黑体。
- 页眉字号为五号。
- 页眉居中。

### 7.3 页脚页码

subject 使用 `global-footer-page-number-*`。

从正文第一页开始，到参考文献、致谢、附录结束，页脚应显示阿拉伯数字页码并连续编排。

原子检查点：

- 正文到附录区域使用阿拉伯数字页码。
- 正文到附录区域页码连续。
- 页码位于页脚中间。
- 页码字体为 Times New Roman。
- 页码字号为五号。

### 7.4 无页码区域

subject 使用 `global-footer-page-number-excluded-*`。

原子检查点：

- 封面不显示页码。
- 中文摘要不显示页码。
- 英文摘要不显示页码。
- 目录不显示页码。

## 8. Cover 模块规则

### 8.2 封面信息行

### 8.3 封面日期

原子检查点：

- 封面日期字号为三号。

## 9. Abstract 模块规则

- 标题字号为三号。
- 标题中文字体为黑体。
- 标题居中。
- 标题后正好 1 个空段落。

### 9.2 中文摘要正文

subject 使用 `abstract-chinese-body-*`。

不检查摘要字数或具体内容。

原子检查点：

### 9.3 中文关键词

- 最后一个关键词后无标点。
- 关键词行字号为小四。
- 关键词行中文字体为宋体。
- 关键词行西文和数字字体为 Times New Roman。
- 关键词行行距为 1.5 倍。
- 关键词行首行缩进 2 字符。

### 9.4 英文摘要标题

## 10. Table Of Contents 模块规则

`table-of-contents` 已有规则保持不变。目录标题和目录条目继续作为当前 `active` 规则使用。

后续仅在发现规范差异时新增规则，不重命名、不复用已发布编号。

## 11. Main Text 模块规则

### 11.1 一级标题

subject 使用 `main-text-heading-level-one-*`。

一级标题只允许中文数字形式，例如 `第一章`，不接受 `第1章`。

原子检查点：

- 一级标题编号形态为 `第X章`，其中 `X` 为中文数字。
- 一级标题编号后正好 2 个普通半角空格再接标题。
- 一级标题中文字体为黑体。
- 一级标题字号为三号。
- 一级标题后正好 1 个空段落。
- 每一章另起一页。

### 11.2 二级标题

subject 使用 `main-text-heading-level-two-*`。

二级标题编号只允许阿拉伯数字点号形式，例如 `2.1`。

原子检查点：

- 二级标题编号形态为 `N.N`。
- 二级标题编号和标题之间正好 1 个普通半角空格。
- 二级标题中文字体为黑体。
- 二级标题字号为四号。
- 二级标题行距为 1.5 倍。
- 二级标题数字和西文字体为 Times New Roman。

二级标题不检查首行缩进。

### 11.3 三级标题

subject 使用 `main-text-heading-level-three-*`。

三级标题编号只允许阿拉伯数字点号形式，例如 `2.2.1`。

原子检查点：

- 三级标题编号形态为 `N.N.N`。
- 三级标题编号和标题之间正好 1 个普通半角空格。
- 三级标题首行缩进 2 字符。
- 三级标题中文字体为黑体。
- 三级标题字号为小四。
- 三级标题行距为 1.5 倍。
- 三级标题数字和西文字体为 Times New Roman。

### 11.4 正文普通段落

subject 使用 `main-text-paragraph-*`。

以 `（1）` 等形式开头的段落不做“三级以下标题”独立规则，但仍按正文普通段落规则检查。

原子检查点：

- 正文普通段落字号为小四。
- 正文普通段落中文字体为宋体。
- 正文普通段落西文和数字字体为 Times New Roman。
- 正文普通段落首行缩进 2 字符。
- 正文普通段落行距为 1.5 倍。
- 正文普通段落两端对齐。

### 11.5 正文参考文献引用

subject 使用 `main-text-reference-citation-*`。

只检查正文中形如 `[数字]` 的引用，不检查引用是否存在对应参考文献条目。

原子检查点：

- 正文引用编号格式为方括号数字，例如 `[1]`。
- 正文引用编号为上标。
- 正文引用编号字号为小四。
- 正文引用编号字体为 Times New Roman。

### 11.6 公式

subject 使用 `main-text-formula-*`。

不检查“公式必须在正文中被引用”。

原子检查点：

- 正文中出现的公式必须有公式号。
- 公式号按章编号，例如第 3 章第 1 个公式为 `(3-1)`。
- 公式和编号整体居中对齐。
- 公式编号居右放置。
- 公式编号字号为五号。
- 公式编号字体为 Times New Roman。

### 11.7 图片题注

subject 使用 `main-text-figure-caption-*`。

不检查图片是否在正文中被引用。

原子检查点：

- 所有图片必须有图题。
- 图题位于图片下方。
- 图号按章编号，例如 `图3-1`。
- 图号与图题之间正好 1 个普通半角空格。
- 图题居中。
- 图题字号为五号。
- 图题中文字体为宋体。

### 11.8 表格题注

subject 使用 `main-text-table-caption-*`。

三线表要求只作为规范说明，不进入第一轮 `active` 或 `draft` 规则。

原子检查点：

- 所有表格必须有表题。
- 表题位于表格上方。
- 表号按章编号，例如 `表4-1`。
- 表号与表题之间正好 1 个普通半角空格。
- 表题居中。
- 表题字号为五号。
- 表题中文字体为宋体。

## 15. 不纳入第一轮规则资产的内容

以下内容不写入第一轮 `rule.yml`：

- 封面示例姓名、学号、院系、专业年级、指导教师、日期的固定值。
- 封面信息行标签存在性。
- 题目是否符合“基于……的设计与实现”模板。
- 三级以下标题独立规则。
- 公式是否在正文中被引用。
- 图片是否在正文中被引用。
- 表格三线表检测。
- 参考文献 GB/T 7714 著录格式细节。
- 正文引用与参考文献条目的交叉匹配。

## 16. 实施顺序建议

1. 更新 `thesis_review/docs/rules/README.md` 的模块表和维护说明。
2. 创建除 `table-of-contents` 外的模块目录、`README.md`、`rule.yml`、`case.yml` 和 `samples/.gitkeep`。
3. 按本设计写入新增模块 `rule.yml`，新增规则先标记为 `draft`。
4. 为每个新模块写最小 `case.yml`，先包含无样本或待维护样本说明，保持结构合法。
5. 运行 catalog 相关测试，确认新增 `rule.yml` / `case.yml` 能被 loader 校验。
6. 后续按模块实现检查器，验证通过后逐条或逐组把规则改为 `active`。
