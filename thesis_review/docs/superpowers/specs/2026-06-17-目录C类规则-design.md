## 1. 背景与目标

项目当前已经完成论文格式审核系统的基础框架：

```text
input.docx -> extractor -> DocumentModel -> rules -> list[Issue] -> annotator -> marked.docx
```

原有 6 条规则主要用于验证框架可用性，规则编号仍是英文内部编号，如 `format.body.font`。后续规则需要直接对齐人工整理的规范编号体系，即 `Axxx/Bxxx/Cxxx/...`。本次先实现目录部分的 C 类规则，规则 ID 在代码、测试、批注输出中均使用业务编号：

- `C001`：目录标题格式
- `C002`：目录条目编号与标题之间的空格
- `C003`：目录条目正文格式

本设计只覆盖目录 C 类规则和支撑这些规则所需的最小模型调整，不扩展封面、摘要、正文、参考文献、图表题注等其它分类。

## 2. 规则来源与样本文档

规则定义来自 `docs/rule/C/INDEX.md`：

- `C001`：“目    录”二字为三号、黑体、居中、1.5 倍行距，中间空 4 个空格，和正文之间空一行。
- `C002`：一级目录编号和标题之间空 2 个空格；二级、三级目录编号和标题之间空 1 个空格。
- `C003`：目录条目中文字体为宋体，小四，1.5 倍行距，不加粗；数字使用 Times New Roman。

样本文档用途：

| 文件 | 预期用途 |
|------|----------|
| `docs/无误版.docx` | 无误基线，`C001/C002/C003` 均不应报错 |
| `docs/rule/C/C001-1.docx` | 目录标题字体、对齐等格式错误 |
| `docs/rule/C/C001-2.docx` | 目录标题文本空格、标题后空行相关错误 |
| `docs/rule/C/C002-1.docx` | 一级目录编号和标题之间空格错误 |
| `docs/rule/C/C002-2.docx` | 二级、三级目录编号和标题之间空格错误 |
| `docs/rule/C/C003.docx` | 目录条目字体等格式错误；如样本同时含 C002 错误，允许同时报出 |

`docs/111.docx` 当前路径不存在；项目中已有 `thesis_review/tests/word/111.docx`，它可继续作为端到端样本文档，但本次 C 类规则验收以 `docs/无误版.docx` 和 `docs/rule/C/*.docx` 为准。

## 3. 总体设计

新增独立规则模块：

```text
thesis_review/src/thesis_review/rules/toc_rules.py
```

该模块只负责目录规则。注册表 `rules/registry.py` 只注册 `C001/C002/C003` 三个规则类。

目录规则共享一个小型定位辅助逻辑：

1. 在 `DocumentModel.blocks` 中寻找第一个目录标题段落。
2. 目录标题段落的识别规则为：去除普通空格、全角空格、制表符后文本等于 `目录`。
3. 目录正文从标题段落后开始。
4. `C001` 要求标题后必须且只能有 1 个空段落。
5. 空段落之后连续匹配目录条目格式的段落构成目录条目范围。
6. 遇到第一个非空且非目录条目的段落时，目录范围结束。

规则不依赖 UNO 对象，仍只读取 `DocumentModel`。UNO 行为只在 extractor 层统一抽取。

## 4. 文档分区设计

后续规则不应各自全篇扫描。实现时应先对 `DocumentModel.blocks` 做语义分区，再让各类规则只处理自己的范围：

```text
C 类规则 -> 只扫目录范围
D 类规则 -> 只扫正文范围
E 类规则 -> 只扫参考文献范围
```

分区层建议放在独立模块：

```text
thesis_review/src/thesis_review/sections.py
```

该模块只负责定位区域，不做格式判断，不产生 `Issue`。规则模块消费分区结果。

### 4.1 分区模型

建议定义轻量范围对象：

```python
class SectionRange(BaseModel):
    name: str
    start: int          # 起始 flow_index，包含
    end: int            # 结束 flow_index，不包含
    block_ids: set[str]
```

公共入口：

```python
def detect_sections(document: DocumentModel) -> dict[str, SectionRange]:
    ...
```

辅助函数：

```python
def blocks_in_range(document: DocumentModel, section: SectionRange):
    ...

def paragraphs_in_range(document: DocumentModel, section: SectionRange):
    ...
```

### 4.2 划分原则

不要只按 H1 一级标题划分。学生文档、WPS 文档和手工排版模板中，很多关键区域不是稳定的 H1：

- `目    录` 通常不是 H1，`outline_level` 可能是 `None`。
- `摘要`、`ABSTRACT`、`关键词` 可能只是居中加粗段落。
- `参考文献`、`致谢`、`附录` 有时是 H1，有时只是普通段落套格式。
- 如果学生误用样式，仅靠 `outline_level` 会漏掉真实区域。

分区应采用“文本锚点优先，H1 辅助”的策略：

1. 先用规范化后的段落文本定位主要边界。
2. `outline_level` 只作为置信度辅助，不作为唯一依据。
3. 规则范围以 `flow_index` 为准，保证和 annotator 的定位契约一致。

文本规范化：

```python
def norm(text: str) -> str:
    return (
        text.replace(" ", "")
            .replace("\t", "")
            .replace("　", "")
            .replace("：", "")
            .replace(":", "")
            .strip()
    )
```

### 4.3 推荐分区边界

第一轮可识别以下区域：

| 区域 | 起点 | 终点 |
|------|------|------|
| `cover` | 文档开头 | 中文摘要前 |
| `abstract_cn` | `摘要` / `摘  要` | `ABSTRACT` 前 |
| `abstract_en` | `ABSTRACT` | `目录` 前 |
| `toc` | `目录` / `目    录` | 目录条目结束 |
| `body` | 第一个真实正文 `第一章...` / `第1章...` | `参考文献` 前 |
| `references` | `参考文献` | `致谢` 或 `附录` 前 |
| `thanks` | `致谢` / `致  谢` | `附录` 前 |
| `appendix` | `附录` / `附  录` | 文档末尾 |

锚点匹配使用规范化文本，例如：

```text
摘要       -> 摘要 / 摘  要
ABSTRACT  -> ABSTRACT
目录       -> 目录 / 目    录
正文       -> 第一章... / 第1章...
参考文献   -> 参考文献
致谢       -> 致谢 / 致    谢
附录       -> 附录 / 附    录
```

### 4.4 目录范围细化

`table-of-contents` 范围不能简单地从 `目录` 到第一个 H1。目录本身常包含 `第一章...`、`第二章...` 等文本，这些不是正文标题，而是目录条目。

目录范围按以下方式确定：

1. 找到目录标题段落。
2. 检查标题后连续空段落数量，正式规则 `table-of-contents-title-006` 要求必须且只能有 1 个。
3. 从空段落后开始收集目录条目。
4. 目录条目匹配一级、二级、三级目录文本和页码。
5. 遇到第一个非空且非目录条目的段落，目录结束。

因此正文起点应避开 `table-of-contents` 范围内的 `第一章...`。只有不在 `table-of-contents` 范围内、且文本匹配 `第一章...` 或 `第1章...` 的段落，才能作为正文起点。

### 4.5 规则消费方式

目录规则：

```python
sections = detect_sections(document)
table_of_contents = sections.get("table-of-contents")
if table_of_contents is None:
    return [issue_factory.create(rule_id="table-of-contents-title-001", ...)]
for para in paragraphs_in_range(document, table_of_contents):
    ...
```

正文规则：

```python
sections = detect_sections(document)
main_text = sections.get("main-text")
for para in paragraphs_in_range(document, main_text):
    ...
```

E 类规则：

```python
sections = detect_sections(document)
references = sections.get("references")
for para in paragraphs_in_range(document, references):
    ...
```

这样规则之间不会共享可变状态，也不会因为某个规则的定位逻辑影响其它规则。分区结果是只读的，每条规则只消费自己需要的区域。

## 5. 模型与遍历契约调整

严格检查 `C001` 的“标题后空一行”需要规则层看到空段落。当前 `uno_traversal.blocks()` 会跳过空段落，因此需要调整文档流模型。

### 5.1 保留空段落

`uno_traversal.blocks(doc)` 应保留空段落，并继续为所有 block 分配连续 `flow_index`：

```text
目    录       -> paragraph block
空段落         -> paragraph block
第一章...      -> paragraph block
```

`ParagraphBlock.text` 为空字符串或仅包含空白时表示空段落。可以新增只读语义字段：

```python
class ParagraphBlock(BlockBase):
    text: str
    is_empty: bool = False
```

实现上允许先不新增字段，直接以 `not para.text.strip()` 判断空段；但如果新增 `is_empty`，需要保证它与 `text.strip()` 语义一致。

### 5.2 run 遍历不变

`uno_traversal.text_portions(para)` 仍只返回非空 text portion。空段落没有 run，annotator 对空段落 issue 不做底纹标注。

### 5.3 定位影响

extractor 和 annotator 都依赖 `uno_traversal.blocks()`，保留空段落后，`flow_index` 会与旧版本不同，但读写仍保持闭环。需要同步更新旧测试中“所有段落非空”的假设，改为“文档流保留空段落，空段落没有 runs”。

## 6. C001 目录标题格式

### 6.1 检查范围

`C001` 只检查目录标题段落及其后紧邻空段落数量。

目录标题段落定位：

- 文本去除普通空格、全角空格、制表符后等于 `目录`
- 取文档中的第一个匹配段落作为目录标题

如果找不到目录标题，报 `C001`，位置锚定到文档第一个可用 block。

### 6.2 检查项

目录标题必须满足：

- 原始文本精确等于 `目    录`，即“目”和“录”之间 4 个普通空格。
- 段落居中：`alignment == "center"`。
- 行距为 1.5 倍：`line_spacing == 1.5`，允许浮点容差。
- 中文字体为黑体。
- 字号为 16pt（三号）。
- 标题后必须且只能有 1 个空段落。

空行规则定义：

```text
目    录

第一章  引言    1
```

上例通过。标题后没有空段落、或标题后有 2 个及以上连续空段落，都报 `C001`。

### 6.3 Issue 定位

所有 `C001` issue 均锚定到目录标题段落。对于“缺少空行”或“空行过多”，也锚定到目录标题段落，因为不存在的空段无法定位，过多空段也不需要逐个标注。

## 7. C002 目录条目空格

### 7.1 检查范围

`C002` 只检查目录条目段落，不检查正文标题。目录条目范围由共享目录定位逻辑提供。

目录条目必须包含页码。实现时优先匹配保留的制表符：

```text
第一章  引言\t1
2.1 线性表的定义\t2
2.2.1 三级标题名\t2
```

如果 UNO 将页码和标题放在同一个 run 中，规则仍以段落 `text` 为准。

### 7.2 一级目录

一级目录格式：

```text
第X章  标题\t页码
```

要求：

- `章` 与标题之间必须正好 2 个普通空格。
- 0 个、1 个、3 个及以上普通空格均报 `C002`。

### 7.3 二级和三级目录

二级、三级目录格式：

```text
2.1 标题\t页码
2.2.1 标题\t页码
```

要求：

- 编号与标题之间必须正好 1 个普通空格。
- 0 个或 2 个及以上普通空格均报 `C002`。

### 7.4 Issue 定位

`C002` issue 锚定到出错的目录条目段落。第一轮不要求精确标注到单个空格 run，因为错误通常是缺失空格或空格数量不对，段落级批注更稳定。

## 8. C003 目录条目正文格式

### 8.1 检查范围

`C003` 只检查目录条目段落，不检查目录标题段落，也不检查正文标题。

### 8.2 检查项

每个目录条目段落必须满足：

- 段落行距为 1.5 倍。
- 所有非空 run 字号为 12pt（小四）。
- 所有非空 run 不加粗。
- 中文字体为宋体。
- 拉丁和数字字体为 Times New Roman。

现有 `RunSpan` 已有 `font_east_asian`、`font_latin`、`size_pt`、`bold` 字段，可支撑第一轮检查。对纯制表符 run，可跳过字体检查，避免因不可见字符导致误报。

### 8.3 Issue 定位

- 段落级错误，如行距错误，锚定到目录条目段落。
- run 级错误，如局部中文字体错误、字号错误、加粗错误，优先锚定到对应 run。
- 如果错误 run 为空白或制表符，锚定到整个目录条目段落。

## 9. 与现有规则的关系

新增规则使用业务编号，不再沿用 `format.toc.*` 这类英文规则 ID。

决策：原有 6 条框架开发阶段规则已从代码中删除，包括 `rules/format_rules.py`、`rules/structure_rules.py` 及其对应旧单测。它们不再进入 `registry.py`，也不作为当前业务规则保留。后续 A/B/D/E/F/G 类规则按业务编号重新实现，不从这些英文内部编号迁移。

后续规则体系工程化后，`C001/C002/C003` 已作为开发阶段编号废弃。目录规则正式编号迁移为 `table-of-contents-title-*` 和 `table-of-contents-entry-*` 原子规则。

目录条目属于论文目录区，不应被正文格式规则重复检查。因此实现本 spec 时，应同步引入 `sections.py`，让目录规则只扫 `table-of-contents` 范围。后续实现正文规则时，应只扫 `main-text` 范围；实现参考文献规则时，应只扫 `references` 范围。

## 12. 风险与处理

### 12.1 空段落改变 flow_index

保留空段落会改变历史测试中的 `flow_index`。处理方式是同步更新 extractor 和 annotator 的共同遍历契约，并用 roundtrip 测试证明读写仍定位到同一 UNO 对象。

### 12.2 Word/WPS 对目录标题拆 run

样本中可能出现“目”和“录”被拆成多个 run 的情况。`C001` 的文本检查以段落 `text` 为准，不要求标题在单个 run 中。字体和字号检查逐 run 进行。

### 12.3 C003 与 C002 同时命中

`C003.docx` 可能同时包含目录条目空格错误。验收时只要求至少命中 `C003`，允许同时命中 `C002`，避免为了测试隔离而掩盖真实文档中的多个问题。

### 12.4 数字字体识别

目录条目中数字和中文可能处于同一 run。第一轮按 run 的 `font_latin` 判断拉丁/数字字体，不做字符级拆分。如果后续发现 Word 对混排字体返回不稳定，再单独扩展字符级或 text portion 级判断。

### 12.5 分区误判

文本锚点优先能覆盖大多数手工排版文档，但仍可能遇到正文中误写“参考文献”或“附录”的普通段落。第一轮通过顺序约束降低误判：`references` 必须出现在 `body` 之后，`thanks` 必须出现在 `references` 之后或文末区域，`appendix` 必须出现在 `thanks` 或 `references` 之后。后续如需更高准确率，可引入样式、居中、字号等辅助置信度。

## 13. 后续工作

本设计实现后，可以继续推进：

1. D 类正文标题/正文范围规则，避免正文规则误扫目录。
2. 参考文献 E 类格式规则。
3. 页眉页脚、页码和目录页码准确性检查。
4. 规则配置化，允许按业务编号选择启用规则。
