# 统一文档流模型重构 — 设计文档

日期：2026-06-14
状态：已实现
对应提交：`52b9110 refactor: use unified document blocks`

> 说明：本 spec 是对已确认设计的追溯补齐。实现前已在对话中确认“不需要做兼容”，但未按工作流先写入 `docs/superpowers/specs/`，这里补齐该设计记录，作为后续表格、图片、题注规则继续开发的依据。

## 1. 背景与目标

原模型只有：

```python
class DocumentModel(BaseModel):
    source_docx: str
    paragraphs: list[ParagraphBlock]
```

这能支持正文段落和 run 级格式检查，但无法表达表格、图片等非段落对象，也无法保留“段落、表格、图片”在 Word 文档流中的相对顺序。

后续规则需要判断上下文，例如“表格前一段是否为表题”“图片后一段是否为图题”。如果把段落、表格、图片拆成多个独立列表，会丢失文档流顺序。因此目标是把文档内容统一建模为有序 block 流，并让规则和标注定位都基于同一套索引契约。

本次明确不做旧 API 兼容：删除 `DocumentModel.paragraphs` 作为模型入口，所有调用方统一迁移到 `DocumentModel.blocks`。

## 2. 核心设计

`DocumentModel.blocks` 是文档内容的唯一事实来源，按 UNO 枚举到的文档流顺序排列。

```text
DocumentModel
├── page_styles
└── blocks
    ├── ParagraphBlock
    │   └── runs
    ├── TableBlock
    └── ImageBlock

Issue
└── Location
    ├── block 定位：paragraph/table/image 整块
    └── run 定位：paragraph 内某个 run
```

### 2.1 Block 模型

所有块共享：

```python
class BlockBase(BaseModel):
    id: str                 # b-0000
    kind: BlockKind         # paragraph | table | image
    flow_index: int         # 文档流全局序号
    type_index: int         # 同类型内部序号
```

`flow_index` 是读写定位的主索引。`type_index` 只表示同类型第几个对象，供规则和调试使用，不参与跨类型定位。

段落块：

```python
class ParagraphBlock(BlockBase):
    kind: Literal["paragraph"] = "paragraph"
    text: str
    style_name: str | None
    outline_level: int | None
    alignment: str | None
    line_spacing: float | None
    first_line_indent_chars: float | None
    page_break_before: bool = False
    runs: list[RunSpan]
```

表格块当前只做整表级抽取和定位：

```python
class TableBlock(BlockBase):
    kind: Literal["table"] = "table"
    row_count: int | None = None
    column_count: int | None = None
    text: str = ""
```

图片块先定义模型边界，UNO 抽取和标注留作后续：

```python
class ImageBlock(BlockBase):
    kind: Literal["image"] = "image"
    name: str | None = None
    alt_text: str | None = None
    width_mm: float | None = None
    height_mm: float | None = None
```

### 2.2 Location 模型

旧定位使用 `kind + paragraph_index + run_index`。新定位统一为：

```python
class Location(BaseModel):
    target: Literal["block", "run"]
    block_id: str
    block_kind: BlockKind
    flow_index: int
    run_id: str | None = None
    run_index: int | None = None
```

约束：

- `target="block"`：定位到整个 `ParagraphBlock` / `TableBlock` / `ImageBlock`
- `target="run"`：只允许 `block_kind="paragraph"`，且必须提供 `run_id` 和 `run_index`
- `block_id` 必须与 `flow_index` 对应的 `b-xxxx` 一致，用作防错校验

## 3. 数据流与模块边界

### 3.1 UNO 遍历契约

`uno_traversal.blocks(doc)` 是 extractor 和 annotator 的共同定位契约。

它按 `doc.Text.createEnumeration()` 枚举文档流中的块级元素：

- 非空段落：`kind="paragraph"`
- 表格：`kind="table"`
- 图片：模型已预留，具体 UNO 枚举策略后续补充

每个枚举结果带 `flow_index` 和 `type_index`。extractor 用它生成 `DocumentModel.blocks`，annotator 用同一函数按 `Issue.location.flow_index` 反查 UNO 对象。

### 3.2 extractor

extractor 不再返回 `paragraphs`，而是返回：

```python
DocumentModel(source_docx=source_path, blocks=blocks)
```

段落抽取保留原有格式字段和 run 字段；run ID 改为：

```text
b-0001-r-0000
```

表格抽取当前实现：

- `row_count`
- `column_count`
- `text`：所有单元格文本拼接得到的摘要

### 3.3 rules

规则层不再访问 `document.paragraphs`。段落规则统一过滤：

```python
for block in document.blocks:
    if block.kind != "paragraph":
        continue
```

这样旧的正文格式、标题层级、必备章节规则仍只处理段落，但不会破坏表格/图片在文档流中的位置。

### 3.4 annotator

annotator 按 `Location.target` 和 `block_kind` 分派：

- 段落块级 issue：对该段所有 text portion 设置红色底纹，并插入批注
- run 级 issue：只对目标 text portion 设置红色底纹，并插入批注
- 表格/图片块级 issue：当前记录 warning 并跳过，保证不影响其他 issue 写回

表格和图片的实际标注策略后续单独设计，避免在本次模型重构中引入不稳定 UNO 行为。

## 4. 页与题注的处理原则

页不是内容流对象，不建 `PageBlock`。显式分页信息挂在段落块字段：

```python
page_break_before: bool = False
```

页边距、页眉、页脚等页面样式信息放在：

```python
DocumentModel.page_styles: list[PageStyleInfo]
```

题注也不在 `TableBlock` 或 `ImageBlock` 中缓存为 `caption_before/caption_after`。题注本质是相邻段落，规则应直接基于 `blocks[flow_index - 1]` 或 `blocks[flow_index + 1]` 判断，避免派生字段和文档流事实不一致。

## 5. 测试与验收

本次重构的验收标准：

- 纯 Python 测试全部通过：

```bash
cd thesis_review
uv run pytest -m "not uno" -q
```

- 容器内 UNO 全量测试通过：

```bash
cd thesis_review
docker run --rm -v "$PWD":/workspace -w /workspace \
  thesis-review-uno-dev \
  /opt/venv/bin/python -m pytest -q
```

- `DocumentModel` 只接受 `blocks` 作为内容入口
- `Location` 校验 block/run 两类定位约束
- 规则层跳过 table/image，只处理 paragraph block
- extractor 抽出的 block ID 满足 `b-{flow_index:04d}`
- run ID 满足 `{block.id}-r-{run_index:04d}`
- roundtrip 测试证明 extractor 的 `flow_index/run_index` 能被 annotator 定位回同一 UNO 对象
- 表格测试证明“段落-表格-段落”的文档流顺序被保留，且表格行列数和文本摘要可抽取
