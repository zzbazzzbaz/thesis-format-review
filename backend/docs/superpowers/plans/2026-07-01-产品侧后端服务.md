# 产品侧后端服务 Implementation Plan

> **For agentic workers:** 本计划用于实现产品侧 Django 后端。严格遵循对应设计文档：`backend/docs/superpowers/specs/2026-07-01-产品侧后端服务-design.md`。实现时不要引入 DRF、Celery、Redis 或 PostgreSQL；使用 Django、Django Ninja、SQLite、本地文件存储和轻量 `review_worker`。

**Goal:** 建设前后端分离的产品侧后端，由 Django 后端负责用户、角色、次数、审核任务、历史记录、下载权限、教师统计和 Django Admin；`thesis_review` 保持独立无状态服务，只通过内网 API 被调用。

**Architecture:** 前端只访问产品侧 Django API。Django API 创建审核任务、扣减学生次数并保存上传文件。轻量后台 worker 从 SQLite 轮询待审核任务，调用 `thesis_review` 的 `POST /api/review`，保存 `marked.docx` 和 `issues.json`，再更新任务状态。Django Admin 负责管理用户、师生关系、次数和任务。

**Tech Stack:** Python 3.12、uv、Django、Django Ninja、SQLite、JWT、本地文件存储、pytest、`thesis_review` HTTP API。

**执行目录:** 除特别说明外，所有命令从 `backend/` 目录运行。


  - [ ] 更新任务统计字段。
  - [ ] 成功时置为 `succeeded`。
  - [ ] 失败时置为 `failed`。
- [ ] 实现 `review_worker` 管理命令。
- [ ] worker 首版只支持单进程运行。
- [ ] worker 支持安全退出和循环间隔配置。
- [ ] 增加测试覆盖成功、失败、超时、multipart 缺失 part 等场景。
- [ ] Perform a self-review of this phase before marking it complete.
- [ ] STOP and wait for human review.

**Worker 伪代码：**

```text
while running:
    task = find oldest pending task
    if no task:
        sleep
        continue

    mark task running
    try:
        artifacts = call thesis_review(source_file)
        save marked_docx
        save issues_json
        update summary
        mark task succeeded
    except expected failure:
        record safe error
        mark task failed
```

**验收标准：**

- 不依赖 Celery 或 Redis。
- worker 可以把 `pending` 任务推进到 `succeeded` 或 `failed`。
- 失败信息不会暴露服务端堆栈或内部路径。

## Important Considerations & Requirements

- [ ] 不引入 Django REST Framework。
- [ ] 不引入 Celery。
- [ ] 不引入 Redis。
- [ ] 不要求 PostgreSQL。
- [ ] 使用 Django Ninja 暴露 API。
- [ ] 使用 SQLite 作为首版数据库。
- [ ] 使用本地文件系统保存上传和审核产物。
- [ ] `thesis_review` 只作为独立无状态服务调用。
- [ ] 学生上传一次扣减一次剩余次数。
- [ ] 下载接口必须做对象级权限校验。
- [ ] 错误响应不能暴露内部路径、堆栈或服务端异常细节。
- [ ] 不添加占位 TODO 代码。
- [ ] 不过度抽象，优先完成可运行的首版产品后端。

## Debugging Protocol

- **上传失败**：先确认文件后缀、文件保存路径和学生剩余次数。
- **任务一直 pending**：检查 `review_worker` 是否运行，检查任务查询条件。
- **任务 failed**：检查 `thesis_review` URL、超时配置、multipart 响应解析和安全错误记录。
- **下载 404/403**：检查对象级权限，不要绕过权限直接暴露文件路径。
- **次数异常**：检查事务、条件扣减和次数流水。
